Guide de mise en ligne

Level Devil, en ligne, de A à Z

Trois services, un seul jeu : le code vit sur GitHub, le site est servi en double (GitHub Pages et un Worker Cloudflare), et Supabase est la vraie base — la seule pièce qui fait office de "backend".

💡 Il n'y a pas de "serveur" séparé. GitHub Pages et le Worker Cloudflare affichent tous les deux le même site statique (HTML/CSS/JS) ; Supabase EST le backend. Avoir les deux hébergements est utile comme miroir/sauvegarde, pas pour répartir un travail entre eux.
🖱️ Zéro ligne de commande. Tout ce guide se fait à la souris, dans le navigateur : upload de fichiers sur github.com, boutons dans le dashboard Cloudflare, éditeur SQL de Supabase. Ni Git, ni Wrangler à installer.

1

Préparer le dossier GitHub

à faire une seule fois, en local

Dézippe le projet que je t'ai envoyé (level-devil.zip). Il contient déjà tout, y compris tes clés Supabase :

level-devil/
├─ index.html, game.html, editor.html
├─ css/, js/  — le jeu, l'éditeur, le moteur
├─ sql/schema.sql  — à coller dans Supabase (étape 5)
├─ wrangler.toml  — lu automatiquement par Cloudflare, tu n'y touches pas
└─ README.md

Retiens bien l'emplacement de ce dossier — à l'étape suivante, c'est son contenu (pas le dossier lui-même) qu'on glissera dans GitHub.

2

Créer le dépôt et uploader les fichiers GitHub

github.com/new → glisser-déposer

Sur github.com/new : nom level-devil, visibilité publique, ne coche aucune case (pas de README/licence — on a déjà les fichiers). Clique Create repository.

Tu arrives sur un dépôt vide, avec un lien bleu « uploading an existing file » au milieu de la page (ou plus tard, le bouton Add file → Upload files en haut à droite). Clique dessus.

⚠️ Le détail qui compte : ouvre le dossier level-devil sur ton ordinateur, sélectionne tout ce qu'il y a dedans (index.html, css, js, sql, wrangler.toml…) puis glisse cette sélection dans la zone d'upload. Ne glisse pas le dossier level-devil lui-même, sinon tout se retrouve un niveau trop bas et rien ne fonctionnera.

Glisser un dossier entier (comme css ou js) fonctionne : GitHub garde l'arborescence. Ce projet fait ~25 fichiers, largement sous la limite de 100 fichiers / 25 Mo chacun d'un upload web.

Une fois les fichiers listés, écris un message en bas (ex. Premier envoi) et clique Commit changes.

3

Activer GitHub Pages GitHub

Settings → Pages

Dans ton dépôt : Settings → Pages (menu de gauche) → sous Build and deployment, choisis Source : Deploy from a branch, puis Branch : main et dossier / (root) → Save.

GitHub prend une à deux minutes pour publier la première fois. L'URL apparaît en haut de cette même page une fois prêt.

Ton site sera à :
https://TON-PSEUDO.github.io/level-devil/

5

Créer la base de données Supabase

SQL Editor → coller → Run

js/config.js contient déjà l'URL et la clé de ton projet Supabase. Il ne reste qu'à créer les tables. Sur ton tableau de bord Supabase → ouvre ton projet → SQL Editor → New query → colle le contenu de sql/schema.sql → Run. Ce fichier est idempotent : si tu avais déjà une base d'une version précédente, le ré-exécuter ajoute juste ce qui manque, sans rien casser.

Ça crée :
tables levels, profiles (comptes) et reports (signalements) · règles de sécurité (RLS) · authentification par compte · fonctions de comptage, likes, approbation et signalement

Vérifie ensuite dans Table Editor : les tables levels, profiles et reports vides doivent apparaître (0 lignes, c'est normal — personne n'a encore de compte ni de niveau publié).

Devenir admin (pour approuver des niveaux en "Parties officielles") : crée d'abord un compte joueur normal depuis le site (page d'accueil → "Créer un compte"), puis, une seule fois, dans SQL Editor :

update public.profiles set is_admin = true
where id = (select id from auth.users where email = 'ton-email@exemple.com');

Connecte-toi ensuite avec ce compte sur admin.html.

6

Vérification finale

les trois pièces ensemble

Le vrai test : publier un niveau depuis une URL et le retrouver sur l'autre — la preuve que Supabase relie bien les deux hébergements.

↻

Mettre à jour le site plus tard

après une modification du code

Comme tout part de GitHub, une seule action met à jour les deux hébergements. Ouvre le fichier à modifier dans ton dépôt GitHub, clique l'icône crayon ✏️ en haut à droite pour l'éditer directement dans le navigateur (ou Add file → Upload files pour remplacer plusieurs fichiers d'un coup — même chemin = remplacement), puis Commit changes.

Ce que ce seul commit déclenche :
GitHub Pages republie en quelques secondes · Cloudflare détecte le commit et relance un build (Settings → Builds → Deployments)
La page GitHub Pages affiche une 404

Vérifie que le dossier choisi dans Settings → Pages est bien / (root) et que index.html est à la racine du dépôt — pas dans un sous-dossier level-devil/ créé par erreur si tu avais glissé le dossier entier au lieu de son contenu (étape 2).

Le Worker Cloudflare ne se met pas à jour après un commit

Va dans Settings → Builds : vérifie que level-devil est bien listé comme dépôt connecté et que la branche surveillée est main. L'onglet Deployments montre le journal de chaque tentative, avec le message d'erreur si un build a échoué.

Je ne retrouve pas mon Worker "leveldevil" dans le dashboard

Vérifie en haut à gauche du dashboard que tu es bien connecté au compte Cloudflare qui possède capkychannel — un même email peut avoir accès à plusieurs comptes.

La publication d'un niveau échoue dans l'éditeur

Vérifie que le script sql/schema.sql a bien été exécuté (étape 5) et que js/config.js contient ton URL et ta clé Supabase (déjà fait dans ce dépôt). Le message d'erreur exact s'affiche sous la barre d'outils de l'éditeur.

Puis-je utiliser un nom de domaine perso (ex: leveldevil.com) ?

Oui : achète le domaine, ajoute-le à ton compte Cloudflare (DNS), puis crée une route personnalisée pour ton Worker (Cloudflare → Workers & Pages → ton Worker → Settings → Domains & Routes), ou configure un domaine personnalisé dans Settings → Pages côté GitHub. Aucun changement de code nécessaire.
